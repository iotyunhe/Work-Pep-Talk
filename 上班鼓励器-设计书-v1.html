这份文档解决什么

它不解释界面长什么样——那个看 UI 稿。它解决三件事：数字怎么算（第 3 节，逐条给公式和边界）、什么时候变脸（第 4 节，状态机阈值）、换背景为什么字还看得清（第 5 节，配色算法）。

凡是需求讨论中已经拍板的，写成规则；凡是没人问过的，我按工程惯例拍板并标注为「默认假设」，不留待确认项。

01项目定位与边界

先把「要什么」「什么不算」「什么算做完」写死。这三句念给不了解背景的人听，他也能判断做得好不好。

1.1 我要什么

一个 300×200 的常驻小窗，贴在屏幕右下角、置顶、可拖动、位置被记住。工资按月薪 / 日薪 / 时薪任一种输入，软件自动折算出日薪与时薪并固定显示两行。主数字是「今天已赚」，每秒递增。同时显示已工作时长与距下班时长。形象随当天进度变脸。改工资后一秒内全界面重算。

1.2 什么不算

  • 不是番茄钟——不做任务清单、不做专注计时、不做休息提醒。
  • 不是记账软件——不做月度报表、不做消费分析、不做趋势图。
  • 不是打卡工具——不记录考勤、不生成工时证明、不上传任何数据。
  • 不靠弹窗打扰——不主动弹通知、不强制置顶打断、不发声（v1）。
  • 不说空话——「加油」「打工人」「你真的超棒」一律不写。

1.3 什么算做完

维度标准
数值正确连续运行 8 小时，金额累计误差 ≤ 1 秒对应金额（约 ¥0.01–0.02）
响应及时修改工资或工时，全界面 1 秒内完成重算
状态可靠跨零点、跨天、休眠唤醒、系统改时间，均能落到正确状态
资源克制空闲 CPU < 1%，常驻内存 < 80MB，不触发风扇
绿色可移整个文件夹拷到任意目录（含 U 盘）双击即用，配置不丢
开机即现登录系统后 3 秒内出现在上次的位置，不需管理员权限

1.4 最关键的一个判断

同类产品都在做倒计时，我们不。倒计时是负反馈——屏幕上永远有一个数字在减少，看久了只会更想跑。真正能支撑人的是增量：数字在涨，说明这段时间换到了东西。

所以视觉中心必须是「今天已赚」，日薪与时薪降级为核对用的辅助信息，已工作与距下班再降一级。这个层级关系是产品的地基，任何后续改动都不能翻转它。

1.5 目标用户与场景

每天坐在电脑前 8 小时以上、工资固定、对「今天又白干了」有体感的人。典型场景：写代码、做设计、写材料、远程办公。打开挂件不是为了被鼓励，是为了把抽象的「上班」变成可数的钱。

2.1 v1 明确不做

历史统计、云同步、账号体系、多语言、声音提醒、任务管理、屏幕使用时长统计、工资条解析。这些都不进 v1，代码结构上也不预留插槽——真要做时再重构，比现在留一堆空接口干净。

范围纪律：v1 只交付「能跑起来且数值对」的最小闭环。自定义形象、夜班、皮肤切换都是 P1/P2，实现顺序排在 P0 全部通过验收之后，避免中途出现「功能都有了但金额算错」。

03计算内核规格

唯一真相来源是 compute(now)，界面所有数字都从它出，不做二次加工。

3.1 输入参数

字段类型默认值取值域与说明
mode枚举monthlymonthly / daily / hourly，决定 value 的含义
value数值8000> 0；≤ 0 时不计算，显示「请先填工资」
daysPerMonth数值221–31，允许小数（如 21.75）
hoursPerDay数值8(0, 24]，允许小数
startMin分钟5400–1439，09:00
endMin分钟10800–1439，18:00；小于 startMin 即视为跨天
lunchStart / lunchEnd分钟720 / 780午休区间 12:00–13:00
excludeLunch布尔true午休是否从工时中扣除

3.2 折算公式

// 三种口径 → 统一的日薪 / 时薪
const daily  = mode === 'monthly' ? value / daysPerMonth
             : mode === 'daily'   ? value
             : value * hoursPerDay;
const hourly = daily / hoursPerDay;

// 分段：扣除午休后的有效工作区间（分钟）
segments() = excludeLunch ? [[startMin,lunchStart],[lunchEnd,endMin]] : [[startMin,endMin]];

// 时长与金额
totalSec  = Σ (段终点 − 段起点) × 60
workedSec = Σ clamp(now − 段起点, 0, 段长) × 60
earned    = hourly / 3600 × workedSec        // 加班时段不再相加
otSec     = max(0, now − endMin) × 60
progress  = totalSec > 0 ? min(1, workedSec / totalSec) : 1

3.3 边界规则（必须逐条实现）

情况处理
加班（now > endMin）金额冻结在 daily，不乘倍率；otSec 独立累计，界面第二格改显示「已加班」
跨天夜班（endMin < startMin）班次拆为 [startMin, 1440] 与 [0, endMin] 两段；若 now < endMin，视为「昨天上的班还没结束」，进度按上一班次计算
午休不在班次内直接忽略午休设置，不退化为负时长
hoursPerDay 与班次时长不一致以 hoursPerDay 为准算时薪；班次只用于算「已工作多久」，两者互不覆盖
时间改动 / 休眠唤醒每 tick 用系统时间重算、不做累加，跳变后自动落到正确状态；唤醒首帧立即重算
金额精度内部按秒算，展示四舍五入到 2 位，不在中间步骤舍入
最容易错的一条：加班时不要把 hourly/3600 × otSec 加进 earned。加了就会显示一个公司根本不会付的数字。锁在日薪是刻意设计，不是实现简化。

04状态机与形象映射

状态由「当天进度比例」判定，不用绝对时间——这样夜班和弹性工时不用单独写分支。

4.1 判定顺序

function moodOf(c) {
  if (c.phase === 'before')   return 'before';      // now < startMin
  if (c.phase === 'overtime') return 'overtime';    // now > endMin
  if (c.progress >= 0.999)    return 'done';        // 正好到点
  if (c.progress >= 0.80)     return 'late';        // 后 20%
  if (c.progress <= 0.12)     return 'early';       // 前 12%
  return 'mid';
}

4.2 六种状态对照

状态图标色形象表情界面文案（元气基调）
未开工灰困、眼睛眯成线还没开工。先把水倒上。
刚开工绿睁眼、微笑开工啦。今天第一块钱已经到账。
进行中绿弯眼笑已经赚了一顿午饭。
临近下班橙眯眼、带困意最后一段啦。剩下的时间在打折。
加班中橙死鱼眼、冒汗加班 1 小时 6 分，这段时间没有钱。
已收工灰张嘴大笑、星星今天到此为止。钱已经落袋。

4.3 状态切换的三条硬规则

  1. 到点即锁。进度到 100% 的那一秒，金额停止增长并把标签换成「已锁定」，不等下一分钟。
  2. 文案只陈述事实。不说「再坚持一下」，只说「还剩 47 分钟，等于 36 块」。可被验证的数字比形容词有力。
  3. 加班文案允许尖锐。日常元气，加班转吐槽——用户明确要求的语气分档，见第 8 节文案库。

4.4 形象切换

内置团子用内联 SVG 绘制，六种表情是六组眼睛与嘴的形状，共用一个身体轮廓。自定义图片时按状态映射到用户上传的图：上传 1 张则全程用它；上传多张则按「上班 / 加班 / 收工」三档轮换，用户可在设置里指定哪张对应哪档。图片统一缩放到 56×56 显示区，保持比例居中，超出裁切。

05视觉规范与背景配色算法

背景可换是这个产品最容易做崩的地方——底色一变，所有文字都可能看不见。解法不是准备九套配色，是让配色由亮度算出来。

5.1 尺寸与层级

元素尺寸说明
主面板300 × 200（自适应高度）圆角 16，内边距 12 / 14
收起态56 × 56 圆球右下角徽标显示整数金额
形象区56 × 56，圆角 14像素皮肤为 52×52 硬描边
主数字28px 衬线 / 25px 等宽tabular-nums，等宽数字防跳动
辅助行10.5px 等宽日薪 · 时薪
双格各占一半，圆角 8已工作 / 距下班
进度条4px 高（像素皮肤 8px）只给颜色不给百分比，避免盯着数字焦虑

5.2 背景配色：亮度驱动

// WCAG 相对亮度，输入 #RRGGBB
function lum(hex) {
  const f = v => { v /= 255; return v <= 0.03928 ? v/12.92 : ((v+0.055)/1.055)**2.4; };
  return 0.2126*f(R) + 0.7152*f(G) + 0.0722*f(B);
}
const dark = lum(bg) < 0.42;   // 0.42 是分界线，实测最稳

5.3 为什么黄底要单独处理

黄（#E3B93F）亮度 0.51，属于浅底，字自动转深色——但红色进度条压在黄底上对比度只有 1.8:1，看上去像没画。所以规则里加一条特例：极亮且高饱和的底色，进度条改用青绿 #2F6B5E。这是实测后补的补丁，不是拍脑袋。

5.4 自定义背景图

图片再花也不能吃掉数字，做法是垫一层 74% 半透明米白 + 18px 高斯模糊 + 轻微提饱和。这样无论用户放的是风景、照片还是纯色块，卡面总是回到「有质感的纸」，数字对比度稳定在可读区间。

不做的事：不自动提取图片主题色去生成配色。早期试过，遇到高饱和图片会算出刺眼组合，且同一张图在不同区域取色结果不稳定。固定衬底是更笨但更可靠的做法。

06交互规格

挂件一天在屏幕上待八小时，任何多余的动效都是干扰。所有交互都要能「不碰它也不出事」。

6.1 鼠标行为

操作结果
右上角图标常驻可见、不抢戏：图钉（窗口置顶开关，实心=已置顶／空心=不置顶）、齿轮（设置）、横线（收成圆球）。三个都是 11px 图标、17px 热区，按住它们不会拖动窗口
按住拖动移动窗口；松开时把坐标写进配置，下次开机回到原位
双击头部在「完整面板」与「56px 圆球」之间切换
右键弹菜单：设置 / 重置今日 / 临时穿透 / 隐藏 / 退出
点击金额短暂显示「日薪 ÷ 每日工时 = 时薪」的换算过程，两秒后消失

6.2 特殊状态处理

场景行为
首次启动强制弹出设置面板，工资未填前主数字显示「请先填工资」，不显示 0.00
点击穿透开启窗口变为鼠标透明，所有点击落到下层；只能从托盘菜单关闭穿透
多显示器按屏幕标识记忆坐标；若上次的屏幕已断开，回落到主屏右下角
分辨率变化记忆坐标越界时夹回可视区域内，不跑到屏幕外
退出写盘后再退出；托盘菜单「退出」才真正关闭，关闭按钮默认只隐藏到托盘
重复启动单实例锁；第二次启动时激活已有窗口，不开新进程

6.3 刷新策略

每秒重算一次并只更新变化了的文本节点，不重建整棵 DOM。进度条宽度的过渡设为 0.5 秒线性，让跳动柔和一些。窗口不可见（被收起或被遮挡）时降为每 5 秒一次，恢复可见立即重算——这是把空闲 CPU 压到 1% 以下的关键。

6.4 键盘与无障碍

挂件常驻但不抢焦点，不出现在 Alt+Tab 列表里。托盘菜单提供「切换到前台」以便纯键盘操作。所有图标按钮带 tooltip，主数字的对比度不低于 4.5:1。

07技术架构与数据契约

Tauri 2.0：Rust 负责窗口、托盘、自启、读写配置；前端只负责画界面和算数。两者通过少量命令通信。

7.1 进程与职责

层技术职责
外壳Rust + Tauri 2.0无边框透明窗口、置顶、托盘、单实例、开机自启、配置文件读写
渲染WebView2 + 原生 HTML/CSS/JS界面绘制、compute() 计算、每秒刷新
配置exe 同级 config.json全部设置与窗口坐标；不写注册表、不写 AppData
形象内联 SVG / 本地图片文件自定义图存在 assets/ 子目录

7.2 配置契约

{
  "version": 1,
  "setup": { "done": false },
  "pay": { "mode": "monthly", "value": 8000,
           "daysPerMonth": 22, "hoursPerDay": 8 },
  "schedule": { "start": "09:00", "end": "18:00",
                "lunchStart": "12:00", "lunchEnd": "13:00",
                "excludeLunch": true },
  "look": { "theme": "paper", "background": "white",
            "bgImage": null, "avatar": "builtin",
            "avatarFiles": [] },
  "window": { "x": 1620, "y": 820, "screen": "DISPLAY1",
              "collapsed": false },
  "behaviour": { "alwaysOnTop": true, "clickThrough": false,
                 "autoStart": true }
}

读取失败或版本不认识时，先备份成 config.bak.json，再用默认值重建，绝不因为一个坏文件让应用起不来。写入用「临时文件 + 原子替换」，避免断电写坏。

setup.done 是首次使用的开关。false 时，pay 里的 8000 / 22 / 8 只是让程序能起来的占位值：界面一律显示「未设置 · ¥— · --:--:--」，启动直接打开设置面板引导填写，绝不拿占位数冒充用户收入。用户在金额框里真的输入过内容、或点了「开始使用」，才置为 true 落盘；此后启动不再打扰。

7.3 关键实现要点

  • 透明窗口需同时设置 transparent: true 与 decorations: false，Windows 下还要关闭窗口阴影，否则圆角外框会出现黑边。
  • 置顶用 set_always_on_top(true)；全屏应用覆盖时由系统接管，不做额外干预。
  • 开机自启由 tauri-plugin-autostart 写 HKCU\Software\Microsoft\Windows\CurrentVersion\Run，卸载时删除该键。
  • 单实例由官方插件实现，第二次启动把已有窗口提到前台。

08文案库

两套语气：日常元气，加班尖锐。切换点不是时间，是「这一刻有没有在赚钱」。

8.1 日常（未开工 / 刚开工 / 进行中 / 临近下班 / 收工）

时机文案示例
未开工还没开工。先把水倒上。
还有 8 分钟，够泡杯茶。
刚开工开工啦。今天第一块钱已经到账。
这一秒开始，时间就在变成钱。
进行中已经赚了一顿午饭。
折算下来，这一小时值 45 块 4。
再来两小时，今天的房租就有着落了。
临近下班最后一段啦。剩下的时间在打折。
还剩 47 分钟，等于 36 块。
已收工今天到此为止。钱已经落袋。
363 块 6，够干点别的了。

8.2 加班（尖锐，但不人身攻击）

时长文案示例
0–30 分钟到点了。这段开始不算钱。
再坐十分钟，就白送十分钟。
30–60 分钟已经白干半小时。老板不会知道，但你知道了。
这半小时，时薪归零。
1 小时以上无偿加班 1 小时 6 分。今天时薪被拉低到 40 块 3。
再坐下去，你今天的平均时薪还在往下掉。
2 小时以上加班 2 小时 12 分。这已经是一顿正经晚饭的时间。
今天的时薪被打到 36 块 1，还在跌。
文案纪律：尖锐指向「这件事没有报酬」，不指向「你很失败」。可以吐槽老板不给钱，不能说用户没用。所有文案必须带一个具体数字——没有数字的句子就是在喊口号。

8.3 动态文案的组装规则

文案由「模板 + 实时数值」拼成，例如 加班 {otDur}，这段时间没有钱。。模板按状态分组，同一状态内每次刷新不换句——只在状态切换的瞬间更换，避免每秒闪字。

22自定义背景图真的显示出来选图或拖图后挂件立刻换成该图铺底，画面看得清（55% 白衬底，不再用会把图糊成色团的毛玻璃），正文仍可读。存进 look.bgImage 的是长边 ≤1200px 的 JPEG data URL（约 200KB），不是原图 —— 原图 4MB 编码成 base64 是 5.7MB，超过 Chromium 单个资源 URL 的长度上限，--wd-photo 整条声明会被丢弃，算出来 background-image 是 none，背景一声不响地不显示。老配置里躺着大图的，启动时自动缩一次并存回。另：URL 必须用单引号包在 style="..." 里，双引号会把属性截断
23窗口高度恒等于内容高度挂件恒为 300×221（六种状态实测都是 221，.wd-tip 单行 17px），面板 300×689、小球 76×76，切换之间不留任何余量 —— 多一像素就会从卡片底下露出窗口底色 #FBFAF7，看着就是「多出来一截白条」。三方对账保证它不漂移：绘制后连量四次（含 rAF、120ms、400ms）、ResizeObserver 盯内容、window.resize 盯窗口本身且强制重报（绕过「这个值报过了」的去重）。宿主侧 ApplySize 也改成拿窗口当前实际宽高比对，不再用缓存的上次报值 —— 否则窗口被外部改大后，页面把正确值重报过来会被当成重复丢掉。验证手法：外部 SetWindowPos 把窗口强行改高 300px，1.6 秒后自行回到 300×221
24收起后展开仍是原来那张宽卡片点小球展开必须回到 300×221 的横向布局，不能变成一条 76px 宽、文字竖着挤成一列的窄条。根因：.wd 原本写 width:100%，宽度跟着视口走 —— 而展开那一瞬间窗口还是收起的 76×76，视口只有 76px，于是挂件按 76px 排版、量出 76×297 报给宿主，宿主照办把窗口设成 76×297；此后这一竖列又量出同样的 76，内容和窗口互相自证，永远不会自己纠正。修法两道：①CSS 把挂件宽度改成设计常量 --wd-w:300px，排版与测量不再受视口影响；②syncSize 上报宽度取 max(300, 实测)，ApplySize 另拦一道「非小球却窄于 299 一律丢弃」。验证：--view ball 下派发真实点击展开，日志由修复前的 设窗 76x297 变为 设窗 300x221；收起→展开连续四轮，每次都是 300×221 与 76×76 交替
